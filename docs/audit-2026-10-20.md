## 二、平台层：还没修的高风险项（需要拍板或需要真机验证）

按「用户会看到什么」排序。

1. **U校园口语题交的是空录音**（高）—— **当前决定：只在前端标注，不接评测**
   `platforms/unipus/speech.py` 1573 行语音评测 + 评分上报整模块**只有测试在调**；
   提交链默认 `self_report_scores=False`（`unipus/submit.py:291`）。
   → 口语/角色扮演题平台记 0 分。修法：提交计划里对 ORAL 类接 `build_voice_evaluation_plan`
   （先干跑），或至少在 warnings 里写明「口语未评测」。

2. ~~**品课提交链路是断的**~~（**已修**）
   服务层新增 `pinco_plan` / `pinco_submit_reviewed`，前端新增「提交计划（复核）」面板；
   走「重新 plan → 内容 digest 比对 → confirm_plan → 提交」。
   ⚠️ 真跑仍被 `submit_payload_confirmed=False` 挡住（设计如此）：要真交，需先按真实抓包确认
   `ACTION_SUBMIT_HOMEWORK` 报文结构，再把该开关打开。

3. **iTEST 能力声明与实现相反**（高，1 行可改但要小心）
   `capabilities.fetch_questions/submit=True`，两个方法却无条件 `raise NotSupportedError`。
   控制台双击 iTEST 考试会直接报错（通用 detail 动作）。
   注意：不能简单把 `submit` 改 False —— 一键自动化的「确认交卷」走的就是
   `/api/assignments/submit`，那会被 501 挡掉。正确做法是让通用方法委托 native 链路，
   或给 detail 动作单独判断。

4. **东软图片资源「可完成」却没实现**（中）
   `COMPLETABLE_RES_TYPES` 含 IMAGE，`play_course` 对未知类型只 warning 返回 False，
   刷课时每张图片计一次失败并吃掉 `limit`。修法：把 IMAGE 移出可完成集合，或记 skipped 不占额度。

5. **东软三处列表不翻页**（中）
   课程 100 条封顶（`resources.py:40`，注释直说「这里不翻页」）、学习任务 200 条、
   考勤连 pageNo/pageSize 都没有。超出部分表现为「没有作业 / 没有考勤」。

6. **东软作业归属 0 命中只记 debug**（中）
   `teachCourseId` 缺失 + 课程名不完全相等时，整门课的作业/测验静默为空 —— 和这次事故同一症状。
   修法：0 命中打 warning，带本学期任务总数与样例课程名。

7. **U校园必修集失败静默变空**（中）
   必修集读失败/解析不到时返回 `{}`，随后 `state_scope="required"` 一个状态都不查，
   教材树看起来像「这学期没有必修」。修法：降级 `state_scope=all` 或返回 `required_error`。

8. ~~**东软 token 过期只能整登**~~（**已修**）
   `APP_REFRESH` 已接：401 → 先 `refresh_token` 续期（不需要密码）→ 再确认一次
   `is_logged_in()` → 都失败才回退密码重登。`refresh_token` 缺失时不会白发请求。
   ⚠️ `APP_REFRESH` 是 [C] 级证据（报文未实测），所以失败一律静默回退，不弄坏原路径。

9. **签到只信列表快照**（中低）
   `ATT_GET`（考勤主表详情）未接，守卫基于列表旧数据；老师重开场次/代签时可能重复提交。

10. **东软取卷 0 题不报错**（中低）
    `paperParts` 整体缺失时返回空 Paper，上层当「没有取到题目」跳过，看不出是解析口径变了。

## 三、接口层：后端有、但没必要留着 / 不该接界面

| 接口 | 位置 | 判断 |
| --- | --- | --- |
| `GET /api/questions` | `server.py:301` + `service.py:815` + `bank/store.py:425` | **死接口**：v1/v2/CLI/文档/测试全无调用。建议连 store 方法一起删 |
| `POST /api/run` | `server.py:623` + `service.py:2060` | **仅测试在调**：文档说「供 CLI/脚本」，实际 CLI 直连 runtime。能力已被 `batch-submit` + CLI `run` 取代，建议删 |
| `GET /api/essays/jobs/<id>` | `server.py:355` | 与 `/api/jobs/<id>` 逐行同实现，重复路由，建议删 |
| `GET /api/users/<...>` | `server.py:293` | 恒 404 的死分支 |
| `service.itest_job` | `service.py:1247` | 无调用方的别名 |
| `/next` 别名 | `server.py:54,267` | 无引用；README 只宣传 `/` 与 `/classic` |
| `POST /api/accounts/<id>/update` | `server.py:442` | **相反**：v2 没接「改标签/用户名」，这是缺入口，不是该删 |

**v1 专用、建议随 v1 退役一起删（不要搬进 v2）**：
批改网评分循环整链（`/api/essays/grade-loop|wait|fetch|history` + `grade_job` +
`pigai/grade_loop.py`）、`/classic` 与 `static/v1.html`、`static/app.js`、v1 的 `PAGE_ALIAS`。

| 功能 | 后端接口真实存在？ | 结论 |

| 顶栏干跑/真提交徽标 | — | **别搬**：任务行与提交计划已经说清楚，重复 |
| 抽屉内平台执行日志 | — | **别搬**：v2 检查器 + 日志页 tab 已覆盖 |
| 「直接改写重交」独立红按钮 | 参数保留 | **别搬**：并成评分面板里的一个勾选即可 |
| v1 的 `PAGE_ALIAS {records, settings}` | — | **别搬**：只服务 classic 老书签 |
