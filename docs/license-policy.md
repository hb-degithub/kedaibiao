# 第三方代码引用政策

> 适用范围：任何被本项目**复制、链接、打包、以子进程调用、或以其他方式并入交付物**
> 的第三方代码与二进制。
>
> **仅阅读源码以理解思路**不受本政策的准入限制，但笔记里引用的事实必须标注来源。

---

## 1. 硬规则

引入任何第三方代码之前，**先完成一次评估并登记到第 3 节的清单，再动代码**。

评估必须回答这七个问题，缺一项即视为未完成：

1. **仓库是否真实可获取**？默认分支、HEAD commit、最近提交时间；
2. **精确许可是什么**？SPDX 标识符；**没有标准 SPDX 标识符的，一律按「不可引用」处理**，
   除非能把完整协议文本读透并确认义务可履行；
3. **LICENSE 原文的关键义务**：署名、保留协议、修改声明、传染范围、商用限制；
4. **是否有 NOTICE / 附加条款 / 商业授权要求**？商业授权渠道是否真实存在（有无联系方式）；
5. **传递依赖的许可**：有没有 GPL / AGPL / 其它 copyleft 混进来；
6. **维护状态**：作者人数、提交窗口、star/fork/issue、是否 archived；
7. **技术可复用性**：语言、平台覆盖面、与本项目的实际重合度。

### 红线（无条件禁止）

- ❌ 任何 **AGPL / GPL / SSPL** 代码进入交付物（无例外；确需使用必须停下来先问）；
- ❌ **无 LICENSE 文件**的仓库代码（默认「保留所有权利」，复制即侵权）；
- ❌ 许可**无法核验**的代码（含只有二进制、无源码、无许可声明的分发物）；
- ❌ 复制他人的**代码、注释、文档文本、命名**——借鉴思路可以，搬运表达不行；
- ❌ 把来源不明的代码片段通过 AI 生成的方式「洗」一遍再并入——这既不解决许可问题，
  也破坏可追溯性。

### 允许

- ✅ 阅读源码理解思路，用自己的语言和结构独立实现；
- ✅ 引用宽松许可（MIT / BSD / Apache-2.0 / ISC）的库作为依赖，前提是保留其许可与声明；
- ✅ 通过包管理器正常依赖（声明在 `pyproject.toml`，有 lock 或版本约束）。

## 2. 决策流程

```
要引入第三方代码
   │
   ├─ 有 LICENSE 文件吗？ ── 否 ──→ ❌ 不可引用（保留所有权利）
   │        │ 是
   ├─ 是标准 SPDX 许可吗？ ── 否 ──→ ⚠ 逐条读义务；商用限制/同等条款传染
   │        │ 是                        → 默认 ❌；确需使用须书面记录并确认可履行
   │        │
   ├─ 是 copyleft（GPL/AGPL/SSPL）？ ── 是 ──→ ❌ 红线
   │        │ 否
   ├─ 通用框架，还是单一平台专用？ ── 单一平台 ──→ ⚠ 复用率评估；通常结论是「不划算」
   │        │ 通用
   ├─ 语言与本项目一致？ ── 否 ──→ ⚠ 跨语言成本 vs 重写成本
   │        │ 是
   └─ ✅ 可作为依赖引入；登记清单，锁版本，更新时重做评估
```

### 3.1 `Yunlk/uai-core` —— ❌ 不可引用（只可借鉴思路）

| 项 | 结论 |
| --- | --- |
| 仓库 | <https://github.com/Yunlk/uai-core>，`main`，HEAD `4628e44`（v0.1.2，2026-09-27） |
| 许可 | **自定义《UAI-Core 非商业使用许可协议 1.0》，无 SPDX 标识符**（GitHub 标 `NOASSERTION`） |
| 关键义务 | 禁止任何商业使用（含 SaaS/付费服务/有偿代做代刷）；衍生作品对外分发须采用**同等条款**；须保留协议与声明 |
| 传递依赖 | 181 个 registry 依赖全为宽松许可，无 GPL/AGPL（唯一含 LGPL 字样的是 `r-efi`，三选一 `OR` 不构成传染） |
| 形态 | **U校园 / Unipus 单平台**的 Rust SDK + CLI，未发布 crates.io |
| 维护 | 单人、7 次提交、5 天开发窗口、1 star、0 fork |
| **判定** | **不能直接依赖**（未发布 + 跨语言）；**不建议 fork**（平台零重合 + 跨语言）；**只能借鉴思路** |

**与本项目的冲突点**：本项目 `pyproject.toml` 声明 `Proprietary`，与
「禁商用 + 衍生作品须同等条款」不可共存。一旦把它并入交付物就产生冲突。

**唯一可用边界**：本机、非商业、自用其预编译 CLI，不进仓库、不分发。
（此判断基于协议文本理解，**不构成法律意见**。）

完整的证据链、可复现命令与 9 条 `未验证` 项见
[docs/research/uai-core.md](research/uai-core.md)。

### 3.2 本项目自身的许可

**待定。** 当前状态：

- 仓库内**尚无 `LICENSE` 文件**；
- `pyproject.toml` 标记 `license = { text = "Proprietary" }`。

含义：保留所有权利，**不得分发**。在选定许可之前，本仓库不应公开、不应打包发布。

选定许可时需要一并决定：

1. 是否允许他人商业使用；
2. 是否要求衍生作品同等条款（若选是，未来就不能再并入非商业许可的第三方代码）；
3. 若要从 `Proprietary` 改为开源许可，第 3.1 节的兼容性判断需**重做**。

## 5. 维护约定

- **每次 `pyproject.toml` 的依赖变更**，都要在同一个 commit 里更新本文件的清单；
- **升级依赖的 major 版本**时重做一次评估（许可可能变）；
- 调研产出一律放 `docs/research/`，必须给出**可核验来源**（URL 或文件路径 + 行号）；
- 未经验证的推断必须显式标注「未验证」——**不得作为决策依据**。
