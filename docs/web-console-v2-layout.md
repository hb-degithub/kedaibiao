# 控制台 v2 · 排版逻辑（demo）

> 状态：**新版就是 `/`**。原控制台移到了 `/classic`（重启后生效），两套界面共用同一份
> 后端契约（`docs/web-console-api.md`），没有新增或修改任何接口。

---

## 0. 这份 demo 想解决什么

v1 的控制台信息密度不低，但**排版的层级是扁的**：左侧栏塞了两段导航、每个页面都是一列
自上而下的 `panel`、说明文字以段落形式散布在内容之间、详情用不同形态的抽屉/展开行。

结果有三个具体症状：

1. **作用域要靠回忆**：平台在左侧栏第二段，顶栏也写了一遍，但切换平台后哪些页面失效、
   哪些数据被过滤，只能从文案里读。
2. **主内容与解释争同一条视觉流**：`<p class="note">` 直接排在表格下面，扫读时不断被打断。
3. **同一件事有多种形态**：作业详情是右抽屉，跑批 detail 是弹窗，账号详情是 `<details>`，
   一行一个交互模型。

v2 不是换皮，是把**排版规则**重写：

| 维度 | v1 | v2 |
| --- | --- | --- |
| 平台作用域 | 左侧栏第二段（可滚走） | **顶栏药丸组**，常驻、当前项高亮、带账号状态点 |
| 左侧栏职责 | 平台 + 功能 + 状态 | **只放功能**，按任务意图分组（工作台 / 内容 / 分析 / 系统） |
| 页面结构 | 标题 + 若干 panel 堆叠 | **页头（标题·作用域·主操作）→ 指标带 → 主列表 + 右侧上下文栏** |
| 详情 | 抽屉 / 弹窗 / `<details>` 三种 | **统一右侧检查器**（inspector），表格行与清单行都进它 |
| 说明文字 | 页面中部的 `.note` 段落 | **页脚「页面说明」折叠块**，默认收起 |
| 表格 | 主内容也是表格 | 表格只做**横向对比**（统计、凭据），主内容用**行式列表** |
| 状态呈现 | 各页各写一套空/错提示 | `state` 组件统一 loading / empty / gate / error 四态 |
| 视觉变量 | 直接写色值 | 全部走 token，深浅色只换 token |

## 1. 排版逻辑

### 1.1 三层结构

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏：品牌 │ 平台药丸组（作用域） │ 连接 · 环境 · 主题 · 归属 · 身份 │ 56px
├──────────┬───────────────────────────────────────────────────────────┤
│ 左轨     │ 页头：标题 + 徽标 + 作用域 + 主操作                        │
│ 功能分组 │ 指标带：4~5 个 KPI（等宽数字、单位、说明）                  │
│ 212px    │ 主体：主列（列表/表单） + 右栏（上下文/摘要）                │
│ 可折叠   │ 页脚：「页面说明」折叠块                                   │
└──────────┴───────────────────────────────────────────────────────────┘
```

- **顶栏是作用域，不是装饰**。平台一旦切换，页头的作用域 chip、指标带、列表查询参数
  同时跟着变；「全部平台」下需要具体平台的页面直接给 gate + 平台快捷按钮，不渲染空表。
- **顶栏右侧是「当前平台 + 当前账号」**：`⇄` 下拉切换该平台的号（换号 = 换 cookie，
  只在多于一个号时出现）；旁边的 chip 是账号信息，点开是账号列表 —— 每行可「切到」，
  也能「详情」进右侧检查器。运行环境（干跑/真跑）从顶栏挪到了概览的「运行参数」。
- **页头是每页的唯一排版起点**：标题、徽标（只读 / 写操作 / DEMO）、作用域、主操作都在
  这一行，扫一眼就知道「我在哪、这页看什么、能做什么」。
- **指标带先给结论**：数字在上（25px，tabular-nums），单位缩小，说明用 11.5px 灰字。
  没有数据时给「—」而不是 0。
- **主体是两栏而不是一长列**：主列承担扫读，右栏只放「解释当前页的摘要」（运行参数、
  配置现状、存储位置）。窄屏时右栏自动落到主列下面（`order: 2`）。
- **说明收进页脚折叠块**：默认收起，展开是一次有意的行为；不再和内容抢注意力。

### 1.2 节奏与字号

| 用途 | 字号 / 行高 | 说明 |
| --- | --- | --- |
| 页面标题 | 21 / 1.25 | 650 字重，`-0.01em` 字距 |
| 面板标题 | 13 / 1.5 | 600 字重，面板头统一 11px 上下内边距 |
| 正文 | 14 / 1.55 | 全局基准 |
| 行标题 | 13.5 / 1.45 | 列表行主信息 |
| 元信息 | 11.5 | 时间、编号、平台名 |
| KPI 数值 | 25 / 1.15 | 等宽数字，单位 13px |

间距阶梯固定为 4 / 8 / 12 / 16 / 22 / 28 / 64，圆角 6 / 10 / 14。
所有数字与 ID 用 `--mono`，`font-variant-numeric: tabular-nums`，避免列不对齐。

### 1.3 行式列表取代表格

主内容行是「状态点 + 主信息 + 右侧操作」三段栅格：

```
●  assignment_id · 平台标签 · [干跑]        ┌ 状态 pill ┐
   #51 · 尝试 1 · 2026-10-17 21:31 · 耗时   └ 明细 / 停止 ┘
```

- 第一列 8px 状态点承担「一眼扫结果」，不需要读文字；
- 主信息可换行，超长 ID 用 `overflow-wrap: anywhere`，不会撑破布局；
- 右侧操作永远贴右，窄屏时落到第二行（`grid-column: 2`）；
- 行可展开（任务记录）时，展开区用虚线分隔，留在行内而不跳页。

表格只保留在**必须横向对齐**的地方：统计页跨平台对比、账号页凭据状态。

### 1.4 统一的状态语义

| 状态 | 组件 | 语义 |
| --- | --- | --- |
| loading | `.skel` 三行骨架 | 只在真的在等后端时出现，不含「正在加载」四个字 |
| empty | `.state`（灰 · ） | 說清楚为什么空、下一步点哪里 |
| gate | `.state-gate`（黄 ⌘） | 作用域不够（没选平台 / 非超管），给出口 |
| error | `.state-error`（红 !） | 后端中文原文 + 「重试」，不做静默降级 |

状态文案一律走 `stateBlock(kind, title, detail, actions)`，页面里不再各写一套。

### 1.5 解释性文字的去处

- 页脚「页面说明」：每条页面为什么这样设计、数据从哪来、边界在哪（3~4 条）；
- 面板内的短提示：`env-note`（12px 灰字），只在需要解释某一块时出现；
- 危险动作：就地横幅（`banner` / `banner.error`），不再塞进段落。

## 2. 交互模型

| 动作 | 行为 |
| --- | --- |
| 切平台 | 顶栏药丸，写进 hash（`#/page/platform`），刷新后停在原处 |
| 导航裁剪 | 左轨按「平台动作 + 能力声明」决定显示：iTEST 没有考勤，就不出现「考勤」页；直接改 hash 访问会退回概览 |
| 切账号 | 顶栏 `⇄` 下拉（多号才显示），调用 `accounts/<id>/activate`，切完刷新当前页 |
| 签到 | 「考勤」页列出场次，只有「可签」的行给按钮；需定位场次必须填经纬度，签完自动回读 |
| 看计划 | 「计划」页按状态（计划中 / 待抓包确认 / 待排期）列出未实现功能，点开有阶段计划与风险 |
| 看账号详情 | 顶栏账号 chip → 下拉里点「详情」，检查器列出平台 / 用户名 / 上次登录 |
| 账号变化 | 新增 / 删号 / 切号 / 重登后自动重读账号 + 平台凭据 + 概览；切回标签页也会同步一次（3s 节流） |
| 核对完成度 | 作业页「读取完成状态」开关 → 逐组回读 `progress/v2`（慢但准）；不读时状态列显示 `—` |
| 提交后状态 | 回读 `finish=True` 的行当场标「已完成」；`计分点 0` 的组得分率 0.0 不等于没交 |
| 看详情 | 统一右侧检查器；表格行、清单行、跑批 detail 都进它，Esc 关闭 |
| 逐条核对 | 作业详情检查器带「上一条 / 下一条」与「提交这个作业」，不用回列表再点 |
| 真提交 | 两步：干跑 → 看每题答案与置信度 →「确认真提交」需要再点一次 |
| 删除/停止 | 两步确认按钮（第一次变成「确认删除」），不用 `window.confirm` |
| 命令面板 | `⌘K` / `Ctrl+K` / `/`，跳功能、切平台、刷新、切主题、退出 |
| 归属筛选 | 超管专属，从顶栏移到概览页动作区（仍影响全局数据作用域） |
| 深浅色 | 顶栏 ◐，偏好只记在 `localStorage.kdb.theme`（不存任何凭据） |

提交计划（干跑）里每一行都带状态点、作业号、备注；检查器底部固定「确认真提交 / 取消」，
避免用户滚回顶部找按钮。

## 4. 组件清单

页面只由这几个原生 class 拼装，不引入第三方组件库；颜色、圆角一律来自 token。

| 组件 | 用途 | 关键 class |
| --- | --- | --- |
| kpi | 指标带的一格：标签在上、25px 等宽数值、下面一行说明 | `.kpis` 自适应网格 / `.kpi` / `.kpi-label` / `.kpi-value` / `.kpi-sub` |
| panel | 内容分块：统一面板头（标题 + 右侧操作）、面板体、可选页脚 | `.panel` / `.panel-head` / `.panel-body`（`.flush` 去内边距）/ `.panel-foot` |
| rowx | 行式列表的一行：状态点 + 主信息 + 右侧操作，可展开详情 | `.list` / `.rowx`（`.clickable`）/ `.mark`（`.ok` `.run` `.warn` `.err`）/ `.rowx-main` / `.rowx-title` / `.rowx-meta` / `.rowx-side` / `.rowx-detail` |
| state | 加载 / 空 / 闸门 / 错误四态，统一由 `stateBlock()` 生成 | `.state` / `.state-icon` / `.state-actions` / `.state-error` / `.state-gate` / `.skel` |
| progress | 完成度横条：教材结构的必修完成度 | `.progress` / `.progress-head` / `.progress-label` / `.progress-value` / `.progress-track` / `.progress-fill`（宽度用 `.w-0 … .w-100`）/ `.progress-caption`；状态 `.is-ok`（≥80%）`.is-warn`（≥40%）`.is-low`（<40%） |
| tabs | 同页内切换视图的分段控件，选中态用 `aria-selected`，窄屏横向滚动 | `.tabs` / `.tab` / `.tab[aria-selected="true"]` |
| inspector | 右侧检查器：所有详情（表格行、清单行、跑批 detail）都进它，Esc 关闭 | `.inspector` / `.inspector-backdrop` / `.panel-drawer` / `.drawer-head` / `.drawer-title` / `.drawer-sub` / `.drawer-body` / `.drawer-foot` |

`progress` 专门承担「完成度」这一类比值：刷课工作区的 `finish_points / total_points`、
必修组数、任务提交进度都归它。当前值与总数写进 `.progress-value`（等宽数字），
补充说明写进 `.progress-caption`（如「已完成 34 / 80 点 · 必修 9 组」）。
填充宽度不写内联 style，只换 `.w-0 … .w-100` 阶梯类；颜色只引用
`--ok / --warn / --danger / --surface-3 / --fg-mute` 等 token，深浅两套主题自动跟随。

## 5. 能力 → 入口映射

这是接新平台时唯一需要对照的一张表。**原则：平台声明了什么，界面才出现什么；
每个操作只在一个地方有入口，工具页兜底。**

### 判定顺序

```
平台动作清单 GET /api/platforms/<name>/actions
  ├─ 有 attendance 或 signin  → 「考勤」页出现（按动作分流形态）
  ├─ 有 study / duration      → 工具页收起它（作业页「刷课」已经覆盖）
  └─ 其余非 builtin 动作      → 工具页列出
平台能力声明 capabilities
  ├─ list_courses 为 false    → 「课程」页不出现
  ├─ list_assignments 为 false→ 「作业」页不出现
  ├─ submit / fetch_questions → 决定行内「提交」出不出（见下）
  └─ native_submit_flow       → 决定「一键全部提交」出不出
```

### 页面 → 依赖

| 页面 | 出现条件 | 代码位置 |
| --- | --- | --- |
| 概览 / 任务 / 运行日志 / 统计 / 账号 / 计划 | 总是出现 | `PAGE_ORDER` |
| 用户 | `is_superadmin` | `PAGES.users.admin` |
| 课程 | `capabilities.list_courses` | `PAGES.courses.requiresCapability` |
| 作业 | `capabilities.list_assignments` | `PAGES.assignments.requiresCapability` |
| 考勤 | 动作含 `attendance` **或** `signin` | `PAGES.attendance.requiresAnyAction` |
| 题库 / 工具 | 需要具体平台（「全部平台」下给 gate） | `PAGES.*.needsPlatform` |

### 动作 → 形态 / 去处

| 动作 | 出现在哪 | 形态 |
| --- | --- | --- |
| `attendance` + `sign`（东软） | 考勤页 | 场次列表 → 逐场签到；需定位场次必填经纬度；签完自动回读 |
| `signin`（品课） | 考勤页 | 签到码 / 链接 → 干跑解析（不发送）→ 二次确认签到 |
| `study`（东软） | 作业页「刷课」 | 课程 + 本次上限 → 调 study 动作（写操作，两次确认） |
| `duration`（U校园） | 作业页「刷课」 | 原生刷课工作区里的「刷时长」 |
| `courses` / `assignments` / `detail` | 专属页面 | 工具页不列（`builtin`） |
| 其余（`resources` / `pending` / `essay` / `exams` / `progress` …） | 工具页 | 通用渲染（`renderEnvelope` 按 kind 分流） |

### 按钮 → 闸门

| 按钮 | 出现条件 | 不满足时 |
| --- | --- | --- |
| 行内「提交」 | `capabilities.submit` **且** `fetch_questions`，且不是 pinco | 显示「不可提交」+ 原因（hover） |
| 一键全部提交 | `platforms[].native_submit_flow` | 按钮不出现（避免必 501） |
| 刷课 | 有 `study` 动作，或平台是 unipus（原生链路） | 按钮不出现 |
| 提交计划（复核） | 平台是 pinco | — |
| 一键自动化 | 平台是 itest | — |
| 评分循环面板 | 平台是 pigai（在作业详情里） | — |

### 工具页的兜底规则

`ACTION_SURFACED_IN` 表里登记的动作，工具页默认收起并在横幅里指路：

```js
study    → 作业页 · 刷课
duration → 作业页 · 刷课（刷时长）
attendance / sign / signin → 考勤页
```

点「照样显示在工具页」可切回全量（开关记在 `state.toolsShowAll`，**切换平台会重置**）。

### 接新平台的检查清单

1. 适配器声明 `capabilities` —— 决定「课程 / 作业」页是否出现、行内提交是否可用；
2. 声明 `native_submit_flow` —— 有原生批量提交链路才为 True；
3. 只读 / 写动作各自 `register(ActionSpec(...))` —— 名字对上 `attendance` / `signin` / `study`
   就会自动进对应页面，**前端一行不用改**；
4. 动作的返回用统一信封（`table` / `detail` / `message`），工具页与检查器自动渲染；
5. 如果某个动作之后做了专属页面，把它加进 `ACTION_SURFACED_IN` 即可从工具页收起。

> 表里的判定条件都能在 `static/next/app.js` 里直接 grep 到：
> `requiresCapability` / `requiresAnyAction`（`PAGES`，约 330 行）、
> `ACTION_SURFACED_IN`（约定义在 `pageTools` 上方）、`canSubmit`（`pageAssignments` 里）。
> 改判定逻辑时请同步改这一节 —— 它是「接新平台不用改前端」这个承诺的落点。

## 6. 实现约束（与 v1 一致）

- **零构建**：`index.html` + `app.css` + `app.js`，改完刷新即生效；没有 npm / 打包器 / CDN。
- **CSP 友好**：服务端下发 `style-src 'self'`，所以**没有任何内联 style**；条形宽度用
  `.w-0 … .w-100` 阶梯类；动态文本一律 `textContent`，只有本地字面量图标用 innerHTML。
- **认证**：HttpOnly Cookie（`kdb_session`），前端不读不写令牌；任意 `/api/*` 401 切登录页。
- **归属过滤**：超管的「归属」下拉在顶栏，只对声明了 `OWNER_SCOPED` 的接口追加 `owner_id`。
- **不展示凭据**：密码框只写不读；后端也不返回明文。

## 7. 文件与扩展方式

```
src/kedaibiao/api/static/
├── index.html     v2 外壳（登录 / 顶栏 / 左轨 / 主区 / 检查器 / 命令面板）
├── v1.html        旧版控制台（/classic）
└── next/
    ├── app.css    设计 token + 布局 + 组件
    └── app.js     状态、请求层、路由、信封渲染、各页面
```

新增一个功能页只需四步：

1. 在 `PAGES` 里登记 `{label, group, needsPlatform, admin?}`；
   - 依赖平台能力的再加 `requiresCapability: 'list_courses'` 这类；
   - 依赖平台动作的加 `requiresAction: 'attendance'` 或 `requiresAnyAction: [...]`；
2. 写 `pageXxx(page, seq)`，用 `pageHead / kpis / panel / renderEnvelope / stateBlock` 组装；
3. 在 `renderPage()` 的分发表里加一行；
4. 如果它取代了某个平台动作的入口，把动作名加进 `ACTION_SURFACED_IN`（工具页会自动收起）。

页面函数拿到 `seq`，异步返回时比对 `state.pageSeq` 丢弃过期响应（快速切页不会串数据）。
需要轮询的页面用 `every(ms, fn)`，离开页面时 `clearTimers()` 统一清理。

## 9. 已知边界（demo 阶段）

- 课程 / 作业 / 工具三页会**真的登录平台**，没有账号时错误态是预期结果；
- 作业页已包含三块写操作入口，全部沿用 v1 的行为：
  - **一键全部提交** → `batch-submit`，进度在检查器里轮询；
  - **刷课** → `course-tree`（只读）+ `brush`（后台任务），工作区里直接看教材结构、
    参数、任务日志与计数，真跑按钮需要点两次；
  - **一键自动化**（仅 iTEST）→ `itest/auto` + `itest/manual` + `assignments/submit`，
    缺答案的题在面板里补，核验不符单独列，交卷按钮两次确认；
- 两个工作区都是「页面内的面板」，不是检查器：它们要长期停留、要看日志流；
- 「考勤」页把考勤能力做成一等入口，**按平台的动作决定形态**：
  - 东软（`attendance` + `sign`）：场次列表 → 逐场签到（需定位的场次要经纬度）；
  - 希沃品课（`signin`）：没有场次，只有「签到码 / 签到链接」→ 干跑解析 → 确认签到；
  - 没有这两个动作的平台（iTEST / U校园 / 批改网）左轨里**没有「考勤」这一项**，
    直接改 hash 访问会退回概览并提示。
  课程 / 作业页同样按 `capabilities` 裁剪；依赖动作清单的页面在清单到手前只显示骨架，
  不会先按默认模式打一次必然 404 的请求；
- 东软的**单元测试 / 测验（任务 type=2）**与作业同一套取卷-交卷链路，
  以前只认 type=3，这类任务被整批过滤掉；现在类型列显示「考试」；
- **课程完成度**用 `progress` 组件画在教材结构顶部（`finish_points / total_points`，
  ≥80% 绿 / ≥40% 黄 / 其余红），必修与全部组数放在 caption 里；
- 所有任务轮询都走同一个 `watchJob(jobId, handlers)`：`onJob / onLog / onDone / onError /
  guard / intervalMs`，定时器登记进 `state.timers`，切页时由 `clearTimers()` 统一清理；
- **「工具」页是兜底入口**：只列还没有专属页面的平台动作。已经在专属页面提供的
  （刷课 / 刷时长 / 考勤 / 签到）默认收起，顶部一条横幅说明「已收起 N 个，去哪儿找」，
  需要时点「照样显示在工具页」切回全量。这样同一个操作不会有两个按钮。
- 统计与题库页已完整迁移；批改网评分循环、品课「计划 → 复核 → 提交」已补上。
- **未实现的功能在「计划」页单独标注**（点开有阶段计划 / 缺口 / 风险），不混进功能页；
  口语评测按当前决定只标注、不接评测链路。
