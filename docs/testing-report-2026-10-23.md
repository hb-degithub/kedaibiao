| **pinco** | `confirm=true` | ✅ **被闸门拦下**：最低置信度 0.35 < 阈值 0.75，拒绝提交（没有发出写请求） |
| **chaoxing** | 同上 | ✅ 明确 501：`capabilities.submit = False`（它的作答在浏览器答题窗口，另有入口） |
| **pigai** | 同上 | ✅ 拒绝并给出**正确去处**：没有取题接口，提交走「作业页 → 该行『评分循环』」 |
| **neusoft / unipus** | 同上 | ✅ 会话失效，报错指向重新登录 |

**关键结论：提交闸门是有效的** —— 置信度不足时，`confirm=true` 也会被拒绝，
不会「悄悄交一份低置信度答卷」。

## 4. 本轮发现并修复的问题

1. **超星作业「全量读取」会整批失败**：逐门打开课程页（浏览器）时偶发
   `net::ERR_TIMED_OUT`，一次抖动就让整页报错。
   → 已给 `list_exams` 的 `page.goto` 加**一次重试**；实测单门 8 条正常。
   全量仍建议逐门读（控制台已是逐门+进度），或避开网络抖动时段。
2. **pigai 干跑提交的报错太笼统**：原来只说「没有取到题目，无法作答」。
   → 现在明确写「批改网没有取题接口，提交走评分循环」，与界面按钮一致。
3. **「等分超时」不等于没交成功**：本次实测取回一篇早前超时的稿子
   （eid `235141973`，92 词）→ **72.5 分**。说明超时只是分数没出来，
   稿子确实交上去了 —— 与评分循环现在的提示一致。

## 4.1 补充（2026-10-26）：品课「过期作业」与截止时间

用真实账号复查品课 15 条作业里的 7 条待做时发现两类问题，都已修：

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 新思想测验（二）（三）干跑报 `6569 课程不存在` | 两门课的作业**已过期**（deadline `2026-12-19 23:59` 之前就截止了，平台 `expired=true`），课程后来被归档；列表接口对那门课回 6569 | ① 逐门读取时容忍「课程级」失败，不让一门坏课拖垮整次定位；② 定位不到时再探一次详情，明确说「作业已过期」；③ 过期作业在出计划前就拒绝 |
| 「截止」列全是「—」 | 品课**列表接口不返回 deadline**（实测），只有详情/题目接口有 | 打开「读取完成状态」时逐条补 `deadline` 与 `expired`，状态列能显示「已过期」 |

另：数电第1次课的计划现在 **0 题需人工、最低置信度 0.765**（≥0.75 阈值），
